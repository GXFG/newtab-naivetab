# 0009. 节假日日历运行时订阅，不打包进扩展

- 状态：已采纳
- 日期：2026-11-07
- 相关代码：`src/logic/calendar/subscriptions.ts`

## 背景

日历 Widget 需要中国节假日与调休数据。两条路：把数据打包进扩展，或运行时从公开日历源拉取 ICS。

节假日数据有两个特点：每年由官方重新公布（打包即过期），且数据源通常是第三方日历服务而非官方 API。

## 决策

运行时按需 `fetch` ICS，解析后缓存，TTL 24 小时；失败时回落到旧缓存。扩展不内置任何节假日数据。

## 被否的方案

- **打包静态数据**：等于在扩展里再分发一份第三方日历数据，条款上比"由用户设备订阅公开日历"更暧昧；而且调休安排每年变化，打包的数据只能靠发版更新，用户会看到过期甚至错误的调休。
- **内置第三方中文日历源（如 oneo.me）作为预设**：这类站点在 Cloudflare 人机验证之后，命令行的完整浏览器请求头也会被 403。扩展内 `fetch` 无法执行 JS 挑战，除非用户已在浏览器里拿到 `cf_clearance`，因此不能作为内置预设——加进去只会让用户看到"订阅失败"。

## 后果

- 依赖网络。首次使用且无缓存时没有节假日数据，需等一次成功拉取。
- 不需要新增权限：扩展已有 `host_permissions: ['*://*/*']`，拉取公开 ICS 不会弹授权框。
- 单次传输在 10KB 量级（gzip），失败可从缓存继续，代价可接受。
- **新增预设源之前必须先验证它对 `fetch` 的响应**。如果目标站点有 JS 挑战或强 UA 校验，验证不通过就不要加——预设列表的每一项都是对用户的承诺。
